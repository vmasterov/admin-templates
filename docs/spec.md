# ТЗ — админка блога

Легенда проекта: простая админ-панель блога. Её задача — дать естественное место каждому типовому
компоненту (Modal, Toast, Form, Select, DataTable, Tabs, Virtual List, DatePicker), а не реализовать
сложную предметную область.

## Пользователь (v1)

- Одна роль — **редактор**: видит всё и может делать всё.
- Редактор — не сущность, а текущая сессия: после входа API возвращает его данные (имя, email).
- Роли и управление пользователями — новое требование темы «Роутинг» (см. «Отложенные требования»).

## Сущности

```ts
Article  { id, title, content, categoryId, tagIds: string[], publishedAt: string | null,
           createdAt, updatedAt }
Category { id, name }
Tag      { id, name }
Comment  { id, articleId, authorName, text, createdAt,
           status: 'pending' | 'approved' | 'rejected' }
```

- **Статус статьи не хранится, а вычисляется** чистой функцией `getArticleStatus(article, now)`:
  `publishedAt === null` → черновик, дата в будущем → запланирована, дата в прошлом → опубликована.
- Категории и теги — фиксированные списки, которые отдаёт API. Страниц управления ими нет.
- Комментарии оставляют читатели на публичной части блога (вне проекта), в админке их модерируют.

## Общие правила

- Все страницы, кроме `/auth` и 404, — защищённые. Неавторизованный пользователь → редирект на `/auth`.
- Авторизованный пользователь на `/auth` → редирект на `/articles`.
- Любое удаление — только через подтверждение в Modal.
- После действия (сохранение, публикация, удаление, модерация) — Toast с результатом или ошибкой.
- Текст статьи — обычная `textarea` (допустим Markdown). Rich-text редактора нет.

## Лейаут (все защищённые страницы)

- **Шапка:** название блога (ссылка на `/`), имя пользователя, кнопка «Выйти».
- **Сайдбар:** меню — «Статьи» (`/articles`), «Комментарии» (`/comments`). Активный пункт определяется
  по префиксу пути.

## Страницы

| URL | Доступ | Страница |
|---|---|---|
| `/auth` | публичная | Вход |
| `/` | — | редирект на `/articles` |
| `/articles` | защищённая | Список статей |
| `/articles/create` | защищённая | Создание статьи |
| `/articles/:id/edit` | защищённая | Редактирование статьи |
| `/comments` | защищённая | Модерация комментариев |
| `*` | публичная | 404 |

### Вход — `/auth`

- **Form:** логин, пароль (оба обязательные), кнопка «Войти».
- Сценарий: редактор входит → переход на `/` (→ `/articles`). Ошибка входа — сообщение в форме.

### Список статей — `/articles`

- **Tabs:** Черновики / Запланированные / Опубликованные.
- **DataTable** статей выбранного статуса: сортировка, фильтры, клиентская пагинация.
  Колонки и фильтры уточняются на дизайне DataTable.
- Действия в строке: «Редактировать» → `/articles/:id/edit`; «Удалить» → Modal → Toast.
- Кнопка «Создать статью» → `/articles/create`.

### Создание / редактирование статьи — `/articles/create`, `/articles/:id/edit`

Один компонент в двух режимах.

- **Form:**
  - Название — Input, обязательное;
  - Категория — Select, обязательное;
  - Теги — Select, мульти-выбор с поиском;
  - «Опубликовать в» — DatePicker, необязательное, прошедшие даты недоступны;
  - Текст — Textarea, обязательное.
- **Кнопки:**
  - «Сохранить черновик» → `publishedAt = null`;
  - «Опубликовать» → дата пустая: `publishedAt = сейчас`; дата в будущем: статья запланирована;
  - «Удалить» (только в режиме редактирования) → Modal → редирект на `/articles` → Toast.
- Несуществующий `:id` → 404.

### Модерация комментариев — `/comments`

- **Virtual List** комментариев: автор, текст, статья, дата, статус.
- Действия: «Одобрить», «Отклонить» → Toast.

### 404 — `*`

- Сообщение и ссылка на `/`.

## Где живут компоненты

| Компонент | Где |
|---|---|
| Form | вход, редактор статьи |
| Select | категория, теги в редакторе статьи |
| DatePicker | «Опубликовать в» в редакторе статьи |
| Modal | подтверждение удаления |
| Toast | результат любого действия |
| Tabs | статусы статей |
| DataTable | список статей |
| Virtual List | модерация комментариев |

## Отложенные требования (сессия 5 каждой темы)

- **Роутинг:** роли (например, admin / editor / author) и страница управления пользователями для admin;
  возврат на исходную страницу после входа.
- **Modal:** стек модалок, фокус-трап.
- **Toast:** очередь с лимитом, ошибки HTTP → Toast.
- **Form:** асинхронная валидация, динамические поля.
- **Select:** асинхронные опции; создание тега, если он не найден.
- **DataTable:** переход с клиентской пагинации на серверную.
- **Tabs:** синхронизация активного таба с URL.
- **Virtual List:** строки динамической высоты.
- **DatePicker:** диапазон дат (фильтр таблицы статей «с — по»), локаль.

## Вне рамок

- Публичная часть блога.
- Rich-text редактор, загрузка изображений.
- Управление категориями и тегами.
- Настоящий бэкенд: используется mock-API (выбор — в теме «HTTP-клиент»).
