# Обновление плана admin-templates — 25.10.2026

Документ дополняет HANDOFF.md и docs/spec.md. Где он им противоречит — действует этот документ.
Источник решений — диалог «Карьерная стратегия» от 25.10.2026 (поиск по прошлым чатам: «вертикальный срез», «бигтех»).

## Зачем меняем план

- Цель изменилась: весной 2027 выход в российский бигтех (Senior Frontend в команду AI-продукта),
  дальше рост в AI Product Engineer → AI Engineer.
- Рынок требует от сеньоров больше, чем фронтенд: фичу целиком (UI + API + данные) и умение работать с LLM.
- Исходный план (~70 сессий: все компоненты в React и Vue) до весны не помещается и не закрывает
  бэкенд и AI. Поэтому вместо библиотеки компонентов — один вертикальный срез.

## Что остаётся как было

- Метод: формализация требований, RADIO, связи на бумаге, core на чистом TS, адаптеры, SOLID, unit-тесты core.
- Core проектируется с расчётом на перенос во Vue без правок.
- Режим обучения: код пишу сам, Claude — ментор и ревьюер (не пишет код за меня).
- Расписание: пн, ср, пт, 6:00–9:00.

## Новая последовательность

### Шаг 1. Доделать роутинг — 3–4 сессии, не больше
Только то, что нужно срезу: конфиг маршрутов, лейаут, guards с заглушкой сессии, `buildPath`, 404,
меню сайдбара, unit-тесты core. Хлебные крошки и заголовок вкладки — можно отложить, если не укладываюсь.
Роли и возврат на исходную страницу после входа — уже отложены, так и остаётся.

### Шаг 2. Вертикальный срез `/articles` (~50 сессий, оценка)

| Блок | Что входит | Сессий |
|---|---|---|
| Фронтенд | core и DataTable на React; минимальные Modal/Toast — только если нужны странице | ~15 |
| Бэкенд (учёба + разработка) | основы SQL и схема БД, индексы, миграции, HTTP-сервер на Node.js, валидация, query builder; API списка статей: серверная пагинация, сортировка, фильтры | ~18–20 |
| AI-фича (учёба + разработка) | фильтры таблицы на естественном языке (см. ниже) | ~8–10 |
| Деплой | хостинг, CI, облачная БД | ~3–4 |
| Запас | | ~5 |

Почему Node.js, а не Python: сейчас учу понятия бэкенда (HTTP, SQL, схема, миграции) на знакомом TS,
а не язык + понятия одновременно. Общие типы фронта и бэка в одном репозитории. Python — позже (фаза D).

Стек бэкенда минимальный: лёгкий HTTP-сервер + query builder. Без NestJS и без настоящей авторизации
в срезе (NestJS и авторизация — после R1).

### AI-фича: фильтры на естественном языке
Пользователь пишет запрос («черновики про React за последний месяц») → сервер вызывает LLM API
со structured output → получает объект фильтров, валидирует по схеме → тот же API списка статей.
Ключ API только на сервере. При невалидном ответе — понятная ошибка, ручные фильтры работают всегда.

## Правки к docs/spec.md

- «Вне рамок → Настоящий бэкенд: mock-API» — больше не так: свой бэкенд на Node.js + Postgres.
- DataTable в срезе — сразу серверная пагинация (было: клиентская, переход на серверную — в отложенных).
- Tabs по статусам на `/articles` — решить на дизайне: минимальные Tabs или фильтр статуса в DataTable.
  Статус по-прежнему вычисляется из `publishedAt`, на сервере — условием в запросе.
- Остальные страницы и компоненты (редактор статьи, Form, Select, DatePicker, Virtual List, `/comments`,
  Vue-реализация) — после R1.

## Правила темпа

- На дизайн одной темы (R + A + D + I + O) — не больше 1–2 сессий, затем код.
  Если дизайн темы занимает столько же, сколько роутинг, — упрощать, а не углублять.
- Ноябрь — втягивание. С декабря раз в 2 недели — RADIO на время (45 мин вслух) как тренировка собеседования.
- Новый пункт добавляется только после видимого результата предыдущего.
